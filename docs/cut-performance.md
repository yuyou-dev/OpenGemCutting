# CUT 与光学性能预算和扩展路线

光学“按设计表面”的当前测量见下节，凹切探索版测量见其后；普通 CUT 基线见 [v0.9.0](#v090-实现与测量)。文末各节记录 v0.8.3 主线修复的历史算法与测量，不沿用旧表宣称新版本性能。这里维护算法边界、可信测量摘要与复测方法，一次性时间线和截图放在被忽略的 `tmp/`。

## 2026-09-25 · 按设计表面的采样与降噪

设计目标：设计师拖动含磨砂面的宝石时画面保持连贯；停手后很快看清磨砂与抛光的对比，而不是等待数秒的颗粒噪点消退。规则见 [光学渲染](architecture/geometry-contract.md#按设计表面)。

原实现每批对每个像素追踪 4 条随机路径 × 3 个色散波段，抛光面也按 Fresnel 概率随机选择反射或折射，所以整幅画面都有噪点；运动与停手时的 45%／70%／100% 分辨率切换会反复清空累积，每批约 150–370 ms 的 GPU 提交还会拖慢整页响应。本轮改为：抛光面确定性分裂（纯抛光像素与全抛光一致，无噪点）；磨砂面加入灯板采样与多重重要性采样；凸体改用 uniform 块中的半空间求交，离开宝石的光线直接读取环境；色散为 0 时只追踪一次；亚像素抖动抗锯齿；显示前做只作用于磨砂像素的边缘感知降噪；批量按 fence 完成时间自适应；采样模式只用 50%／100% 两档，缓动剩余不足半像素即按静止累积。

同条件测量：M1 Max，系统 Chrome 无头模式（ANGLE Metal），1280×760 视口、DPR 2，画布内部 1100×587；样本为实验室带回的 177 面设计（冠部 90 面磨砂 α 0.28），无色钻石（折射率 2.417、色散 0.044），柔光摄影棚，检查器展开。拖动为 4 秒、约 60 Hz 的真实鼠标输入；数值为 3 次运行的范围。

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 拖动帧率（50%／45% 分辨率） | 约 11 fps，每帧约 87 ms，满屏颗粒 | 约 30 fps，p95 36 ms，磨砂面平滑、抛光面清晰 |
| 停手后首个画面 | 272 ms（4 样本，噪点明显） | 约 30 ms（1 样本，已降噪） |
| 画面基本干净 | 128 样本仍有颗粒 | 约 160 ms（8 样本），16 与 128 样本肉眼接近 |
| 累积到 128 样本 | 5.8 s | 2.4–2.7 s，随后停止 |
| 主线程帧间隔 p95（拖动中） | 34 ms | 19 ms |

同一设计加四个圆柱凹切（393 个边界面片，走 BVH 网格路径）：拖动约 21 fps，8 样本约 0.55 s，128 样本约 9 s。对照：同场景全抛光 WebGPU 拖动约 51 fps，WebGL2 约 19 fps；WebGL2 的纹理取数是主要成本，所以凸体磨砂改用常量内存中的平面。数值只说明这台设备与此样本上的相对变化，不是跨设备帧率承诺。

正确性核对：把 90 个磨砂面的 α 改为 0.001，收敛画面与全抛光 WebGL2 的平均亮度为 205.9 与 206.9（8 位），平均逐通道差 2.8，差异来自抗锯齿边缘；在 256 样本下读取线性累积缓冲，仅 BSDF 采样、仅外侧反射灯板采样、仅内侧出射灯板采样与完整灯板采样四种变体的区域均值为 0.40691–0.40693，确认灯板采样与多重重要性采样没有引入偏差。另在 CPU 上以均匀采样暴力积分核对单个粗糙边界的两种估计。降噪只作用于显示，不参与上述线性比较。

复测：`npm run dev` 后临时 `npm i --no-save puppeteer-core`，用系统 Chrome（`--use-angle=metal`）在同一视口打开样本项目，进入光学仿真并切到按设计表面；记录 `data-samples` 随时间的变化、拖动期间 `fenceSync` 提交间隔与主线程 `requestAnimationFrame` 间隔，再比较截图。一次性脚本与结果放在被忽略的 `tmp/`，不进入仓库。

## 2026-09-22 · 交互线程与渐进清晰度

上一轮缩短了布尔求解，但单次 V 槽约 44ms、球坑约 131ms 仍阻塞界面。本轮把连续凹切求解放入模块 Worker，复用完整验证与正式 application 能力，不降低曲面分段或几何精度。只保留一个在途与最新待算位置；松手复用最终结果及其缓存，单次撤销恢复整段拖动。确定性回归中，计算未完成期间输入 100 个位置只执行首个和最终位置两次，不堆积过期轨迹。更复杂组合仍受单次求解时间限制，此改动主要释放主线程，不宣称内核本身又加速一倍。

浏览器在 PC 07.001C 预设加五重 V 槽后连续移动 45 次，最终深度 0.78，一次撤销恢复 0.65；主线程 CPU 采样中未出现布尔／工具准备求解函数。该采样用于确认线程归属，不作为端到端帧率统计。

光学采用同一物理追踪器的空间细化：拖动以目标分辨率的 45% 绘制，停下后经过 70% 恢复至 100%；新输入撤销未执行的旧细化。每阶段像素数约为完整帧的 20%／49%／100%，反射次数、材质、色散和几何保持原值。WebGPU 与 WebGL2 都复用已有一次在途、最新请求优先调度。全抛光不是路径追踪时间累积（按设计表面的累积见上节），也不能中止已进入 GPU 的工作。实测 1280×720 视口中长边从 1100 降至 495，停止后恢复 1100；不是固定 FPS 承诺。参考同级 FacetLab 的交互分辨率策略，没有引入其另一个渲染器。

## 2026-09-22 · 凹切探索版性能清理

设计目标是让设计师拖动凹切深度／方向时及时看见实体，松手不再明显停顿。本轮不改变刀具分段数、平面容差、切割次序或参数格式，也不减少闭合、壳层和自相交验证。

CPU 采样确认旧路径是每个重复刀具对整体实体做一次 BSP 差集，并非独立挖每个刻面；但每次都重整整个结果，再把多边形拆成中心扇形三角片。随后严格网格验证、全部平切重放和逐面刀具绘制进一步放大了成本。自相交检查原本已有 BVH，并非无筛选的全量面两两比较。

本轮实现：

- CSG 保留凸多边形与 T 接边，完全相同坐标直接复用焊接结果；不改变真实边界或曲面精度。
- 包围盒证实互不相交的刀具合成一个多壳实体求差；其他刀具使用顺序 BSP 批量入口，只重整最终结果。
- BVH 使用成对节点遍历，避免每个三角形重新遍历整棵树；维持原精确相交与壳层判定。
- 不可变 fixed cuttingReference 跨命令共享；最近一次准备结果及相同输入的平切前缀可复用，完整参数键失配即重新求解。
- 半透明刀具使用一份带逐顶点颜色的 GPU 网格，整组一次绘制；相机改变时复用，工具／尺度变化和卸载时释放旧缓冲。

## v0.9.1 光学调度边界（历史；交互分辨率已由上节更新）

光学仿真使用 GPU fence 非阻塞检查，最多保留一次在途提交，并合并等待期间的观察请求为最新状态。当时的确定性渲染器每次绘制就是完整图像，静止后不做无收益的重复采样；拖动与静止采用同一质量设置，渲染缓冲长边上限 1100 像素。实现见 `src/components/opticsRenderScheduler.js` 与 `OpticsViewport.jsx`。

这改善请求堆积，不降低单次光学求交成本，也不是外部光学实验室的全量迁移。复杂模型或高反射次数仍可能产生较长单帧延迟。下方 v0.9.0 的 CUT 测量保留原口径，不作为本次光学性能数据；10000 面基准是领域内核研究负载，当前 UI 的 OBJ 初始晶体导入上限为 1000 面。

### 剩余瓶颈与下一步

- 每刀共享顶点分类、边交点缓存、边界遍历和紧凑化是 O(V + I)，截面多环与孔归属另有 O(R·K + Ttri(K))；N 刀仍对 N 个演进实体求和。96 刀没有被视为一刀，10000 面 × 96 刀仍明显超过 20ms。
- 凹体导入包含局部拓扑验证、BVH 三角相交及壳嵌套检查。当前中位分割 BVH 每层排序，构建 O(T log²T)，候选重叠或大量壳时可退化到 O(T²)；深凹星柱的重叠投影使 10k 导入成为秒级工作。还存在 OBJ 验证后实体构造再次校验的成本，可沿已验证不可变输入的内部信任边界消除，不能删除自交检查。
- 凸来源首次适配验证闭合拓扑和全部外向半空间，成本 O(F·V)，随后缓存；热路径的容差兼容检查仍有 O(N·(F+N))。前缀缓存、固定法向拖动时的拓扑复用及局部相交前沿，是下一轮应分别测量的优化；拓扑事件必须切回完整求解以保持几何与保存策略。
- 当前没有证明“1000 条独立切割平面实时预览”或“所有输入到画面在 20ms 内完成”。Worker 可改善导入/大批次时主线程响应，但不能冒充内核变快；应在减少重复验证、几何分配与重复批次求解后再决定调度方式。

### v0.9.0 实时正交图专项测量

真实 in-app 浏览器中，以 1000 个源面片的星形晶体生成 30 份不同切深结果（末份 1042 面片），每份按 640 × 480 像素渲染顶视和侧视两图。包含新几何 CPU 缓冲准备、GPU 上传、两个深度绘制及画布拷贝，中位 **2.2ms**、P95 **2.8ms**；不含 CUT 求解、React 其余更新、浏览器合成与屏幕呈现。这只证明双正交预览该项在本机低于 10ms，不能外推为任意模型或完整交互 20ms。

像素回归同时确认：窄前景正确遮挡后景粉色面与黑色边线，可见后景仍为原选中粉色，外围保持白底。三角片与真实边完整参与深度测试，没有简化模型、取消实时预览或改用面心排序。PDF 和静态 SVG 继续保留原精确矢量出口。

该优化阶段，同一千面场景的输入至最后 GL clear 观测中位从约 110ms 降至约 55ms；这是阶段定位指标，尚非屏幕呈现延迟。该阶段记录保留用于定位收益，以下生产测量为更新后的观察值。
