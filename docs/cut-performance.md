# CUT 与光学性能预算和扩展路线

光学“按设计表面”的当前测量见下节，凹切探索版测量见其后；普通 CUT 基线见 [v0.9.0](#v090-当前实现与测量)。文末各节记录 v0.8.3 主线修复的历史算法与测量，不沿用旧表宣称新版本性能。这里维护算法边界、可信测量摘要与复测方法，一次性时间线和截图放在被忽略的 `tmp/`。

## 2026-09-25 · 按设计表面的采样与降噪

设计目标：设计师拖动含磨砂面的宝石时画面保持连贯；停手后很快看清磨砂与抛光的对比，而不是等待数秒的颗粒噪点消退。规则见 [光学渲染](architecture/geometry-contract.md#按设计表面)。

原实现每批对每个像素追踪 4 条随机路径 × 3 个色散波段，抛光面也按 Fresnel 概率随机选择反射或折射，所以整幅画面都有噪点；运动与停手时的 45%／70%／100% 分辨率切换会反复清空累积，每批约 150–370 ms 的 GPU 提交还会拖慢整页响应。本轮改为：抛光面确定性分裂（纯抛光像素与全抛光一致，无噪点）；磨砂面加入灯板采样与多重重要性采样；凸体改用 uniform 块中的半空间求交，离开宝石的光线直接读取环境；色散为 0 时只追踪一次；亚像素抖动抗锯齿；显示前做只作用于磨砂像素的边缘感知降噪；批量按 fence 完成时间自适应；采样模式只用 50%／100% 两档，缓动剩余不足半像素即按静止累积。

同条件测量：M1 Max，系统 Chrome 无头模式（ANGLE Metal），1280×760 视口、DPR 2，画布内部 1100×587；样本为实验室带回的 177 面设计（冠部 90 面磨砂 α 0.28），无色钻石（折射率 2.417、色散 0.044），柔光摄影棚，检查器展开。拖动为 4 秒、约 60 Hz 的真实鼠标输入；数值为 3 次运行的范围。

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 拖动帧率（50%／45% 分辨率） | 约 11 fps，每帧约 87 ms，满屏颗粒 | 约 30 fps，p95 36 ms，磨砂面平滑、抛光面清晰 |
| 停手后首个画面 | 272 ms（4 样本，噪点明显） | 约 30 ms（1 样本，已降噪） |
| 画面基本干净 | 128 样本仍有颗粒 | 约 160 ms（8 样本），16 与 128 样本肉眼接近 |
| 累积到 128 样本 | 5.8 s | 2.4–2.7 s，随后停止 |
| 主线程帧间隔 p95（拖动中） | 34 ms | 19 ms |

同一设计加四个圆柱凹切（393 个边界面片，走 BVH 网格路径）：拖动约 21 fps，8 样本约 0.55 s，128 样本约 9 s。对照：同场景全抛光 WebGPU 拖动约 51 fps，WebGL2 约 19 fps；WebGL2 的纹理取数是主要成本，所以凸体磨砂改用常量内存中的平面。数值只说明这台设备与此样本上的相对变化，不是跨设备帧率承诺。

正确性核对：把 90 个磨砂面的 α 改为 0.001，收敛画面与全抛光 WebGL2 的平均亮度为 205.9 与 206.9（8 位），平均逐通道差 2.8，差异来自抗锯齿边缘；在 256 样本下读取线性累积缓冲，仅 BSDF 采样、仅外侧反射灯板采样、仅内侧出射灯板采样与完整灯板采样四种变体的区域均值为 0.40691–0.40693，确认灯板采样与多重重要性采样没有引入偏差。另在 CPU 上以均匀采样暴力积分核对单个粗糙边界的两种估计。降噪只作用于显示，不参与上述线性比较。

复测：`npm run dev` 后临时 `npm i --no-save puppeteer-core`，用系统 Chrome（`--use-angle=metal`）在同一视口打开样本项目，进入光学仿真并切到按设计表面；记录 `data-samples` 随时间的变化、拖动期间 `fenceSync` 提交间隔与主线程 `requestAnimationFrame` 间隔，再比较截图。一次性脚本与结果放在被忽略的 `tmp/`，不进入仓库。

## 2026-09-22 · 交互线程与渐进清晰度

上一轮缩短了布尔求解，但单次 V 槽约 44ms、球坑约 131ms 仍阻塞界面。本轮把连续凹切求解放入模块 Worker，复用完整验证与正式 application 能力，不降低曲面分段或几何精度。只保留一个在途与最新待算位置；松手复用最终结果及其缓存，单次撤销恢复整段拖动。确定性回归中，计算未完成期间输入 100 个位置只执行首个和最终位置两次，不堆积过期轨迹。更复杂组合仍受单次求解时间限制，此改动主要释放主线程，不宣称内核本身又加速一倍。

浏览器在 PC 07.001C 预设加五重 V 槽后连续移动 45 次，最终深度 0.78，一次撤销恢复 0.65；主线程 CPU 采样中未出现布尔／工具准备求解函数。该采样用于确认线程归属，不作为端到端帧率统计。

光学采用同一物理追踪器的空间细化：拖动以目标分辨率的 45% 绘制，停下后经过 70% 恢复至 100%；新输入撤销未执行的旧细化。每阶段像素数约为完整帧的 20%／49%／100%，反射次数、材质、色散和几何保持原值。WebGPU 与 WebGL2 都复用已有一次在途、最新请求优先调度。全抛光不是路径追踪时间累积（按设计表面的累积见上节），也不能中止已进入 GPU 的工作。实测 1280×720 视口中长边从 1100 降至 495，停止后恢复 1100；不是固定 FPS 承诺。参考同级 FacetLab 的交互分辨率策略，没有引入其另一个渲染器。

## 2026-09-22 · 凹切探索版性能清理

设计目标是让设计师拖动凹切深度／方向时及时看见实体，松手不再明显停顿。本轮不改变刀具分段数、平面容差、切割次序或参数格式，也不减少闭合、壳层和自相交验证。

CPU 采样确认旧路径是每个重复刀具对整体实体做一次 BSP 差集，并非独立挖每个刻面；但每次都重整整个结果，再把多边形拆成中心扇形三角片。随后严格网格验证、全部平切重放和逐面刀具绘制进一步放大了成本。自相交检查原本已有 BVH，并非无筛选的全量面两两比较。

本轮实现：

- CSG 保留凸多边形与 T 接边，完全相同坐标直接复用焊接结果；不改变真实边界或曲面精度。
- 包围盒证实互不相交的刀具合成一个多壳实体求差；其他刀具使用顺序 BSP 批量入口，只重整最终结果。
- BVH 使用成对节点遍历，避免每个三角形重新遍历整棵树；维持原精确相交与壳层判定。
- 不可变 fixed cuttingReference 跨命令共享；最近一次准备结果及相同输入的平切前缀可复用，完整参数键失配即重新求解。
- 半透明刀具使用一份带逐顶点颜色的 GPU 网格，整组一次绘制；相机改变时复用，工具／尺度变化和卸载时释放旧缓冲。

## v0.9.1 光学调度边界（历史；交互分辨率已由上节更新）

光学仿真使用 GPU fence 非阻塞检查，最多保留一次在途提交，并合并等待期间的观察请求为最新状态。当时的确定性渲染器每次绘制就是完整图像，静止后不做无收益的重复采样；拖动与静止采用同一质量设置，渲染缓冲长边上限 1100 像素。实现见 `src/components/opticsRenderScheduler.js` 与 `OpticsViewport.jsx`。

这改善请求堆积，不降低单次光学求交成本，也不是外部光学实验室的全量迁移。复杂模型或高反射次数仍可能产生较长单帧延迟。下方 v0.9.0 的 CUT 测量保留原口径，不作为本次光学性能数据；10000 面基准是领域内核研究负载，当前 UI 的 OBJ 初始晶体导入上限为 1000 面。

### 剩余瓶颈与下一步

- 每刀共享顶点分类、边交点缓存、边界遍历和紧凑化是 O(V + I)，截面多环与孔归属另有 O(R·K + Ttri(K))；N 刀仍对 N 个演进实体求和。96 刀没有被视为一刀，10000 面 × 96 刀仍明显超过 20ms。
- 凹体导入包含局部拓扑验证、BVH 三角相交及壳嵌套检查。当前中位分割 BVH 每层排序，构建 O(T log²T)，候选重叠或大量壳时可退化到 O(T²)；深凹星柱的重叠投影使 10k 导入成为秒级工作。还存在 OBJ 验证后实体构造再次校验的成本，可沿已验证不可变输入的内部信任边界消除，不能删除自交检查。
- 凸来源首次适配验证闭合拓扑和全部外向半空间，成本 O(F·V)，随后缓存；热路径的容差兼容检查仍有 O(N·(F+N))。前缀缓存、固定法向拖动时的拓扑复用及局部相交前沿，是下一轮应分别测量的优化；拓扑事件必须切回完整求解以保持几何与保存策略。
- 当前没有证明“1000 条独立切割平面实时预览”或“所有输入到画面在 20ms 内完成”。Worker 可改善导入/大批次时主线程响应，但不能冒充内核变快；应在减少重复验证、几何分配与重复批次求解后再决定调度方式。

### v0.9.0 实时正交图专项测量

真实 in-app 浏览器中，以 1000 个源面片的星形晶体生成 30 份不同切深结果（末份 1042 面片），每份按 640 × 480 像素渲染顶视和侧视两图。包含新几何 CPU 缓冲准备、GPU 上传、两个深度绘制及画布拷贝，中位 **2.2ms**、P95 **2.8ms**；不含 CUT 求解、React 其余更新、浏览器合成与屏幕呈现。这只证明双正交预览该项在本机低于 10ms，不能外推为任意模型或完整交互 20ms。

## v0.8.3 更新路径（历史基线）

滑杆、数值框和 3D 手柄通过统一 CUT 事件更新草稿，草稿解析、影响检查、实体预览与 helper 使用同一次 React 提交的参数。不能单独延后实体几何，造成杆子已经前进、宝石仍显示旧切面的错位。提交时仍从当前草稿重新执行影响检查。

普通深度调整不会改变已提交实体、Meet 来源拓扑或下一交点候选集合；只重新定位相邻候选，候选身份或求解参数改变时才重新做该候选的完整影响分类。角度、索引、重复、镜像、区域、来源实体和 Meet 约束仍是求解依赖。

视觉裁切采用 geometry 的尺度相关容差，影响检查保留 meetJump 的既有容差。两者不能仅因平面相同就合并；编辑层还必须在原序位替换，以保留重合面的归属。优化不得通过放宽容差、跳过最终有效面判断、降低 helper 采样密度或省略隐藏层的提交检查来换取速度。

## v0.8.3 的 96 分度巡查与适配

本轮先巡查几何消费者，再接入独立的 `clipPolyhedronPreview`。它把源实体边界和本次 CUT 半空间一起求交：原有面直接裁剪，新面在自身平面上求交，最后一次焊接与组装。并非构建通用非凸 CSG 网格再做布尔运算。

| 关联功能 | 巡查风险 | 当前适配 |
| --- | --- | --- |
| Meet / Jump 与旧 JSON | 最终一次焊接可能改变亭尖邻接、法线和 1e-9 来源签名 | 保存实体、施工前缀、持久身份解析仍走顺序内核；批量结果不作为 Meet 来源，不改签名规则 |
| 覆盖、空切与保存保护 | 视觉与影响检查容差不同 | 实时影响检查也可批量求交，但独立保留 1e-8；提交重新执行顺序精确检查，保留 block/warn/confirm |
| 编辑、显隐、群组 | 中间层替换位置及隐藏来源不能丢失 | 编辑预览按原位替换后完整平面序列求交；提交与隐藏层检查保持原逻辑；群组仅预览走批量 |
| 切割助手 | 逐步、随机跳转、缓存续切必须一致 | 完全保留逐刀顺序内核及原缓存，不能拿整组终态替代步骤 |
| ASC / PDF / 切割指令 | 有效面来源决定最终出口 | 导出及已保存统计继续读取顺序内核结果；临时预览保留显式面 ID 和图层来源 |
| 3D / 正交预览 | 缓存失效、绕序、透明顺序、拾取和遮挡 | immutable 几何引用驱动缓存；保留面排序及全部线段，缓存 GPU 网格、批量绘制，正交棱合为独立子路径 |
| 光学仿真 | 原 192 平面截断会漏掉 96+96+台面 | 遍历完整有效平面，浮点纹理按实际 GPU 容量分行，超容量明确报错；不截断实体 |

少于 16 个输入面、匿名或冲突面 ID、逐面容差覆盖及系数不完全相同的近共面边界采用顺序路径；它们不能被无条件套入批处理。批量预览使用相同几何精度，但不保证与逐刀焊接有相同顶点编号或尖点微小分裂；因此它不是新的保存内核，也不能作为拓扑来源。既有顺序内核仅把焊接桶的字符串索引改为数值嵌套 Map，保留邻桶和代表点的选择顺序。

## v0.8.3 算法复杂度

令 P 为输入裁切平面数，F/V/E 为当前实际有效面、顶点和棱数，I 为全部面的顶点引用数，K 为本次截面的候选点数，H 为 helper 遮挡样点数。闭合凸多面体通常 I=2E，且 V/E/I=O(F)；输入一万条重复平面不能冒充一万个有效面。符号键和持久化来源记录的长度也会影响实际成本。

| 路径 | 修复前 | 当前实现／边界 |
| --- | --- | --- |
| 顶点来源拓扑 | 每个顶点扫描全部面，O(VI) | 一次面排序建立邻接，再生成并排序顶点结果，通常 O(F log F)；持久化键、签名和稳定排序保持一致 |
| 截面候选点去重 | O(K²) | 大截面使用已有空间桶，固定 27 个邻桶和原欧氏距离判定；通常 O(K)，保留最早代表点。小截面保留低开销扫描 |
| 一次平面裁切 | 全面裁切／重建，加 K² 去重 | 仍需遍历 I、全量重建和顶点排序，通常 O(F log F + K log K)；共线简化的多轮循环仍可能更差 |
| 新建 N 面 CUT | N 次顺序裁切，逐刀全量焊接／法线／面索引／体积重建 | 适用输入独立求边界交集，最终组装一次；仍保留两种容差和下一候选分类缓存。令 M=F+N、L 为中间单面顶点数，裁剪上界 O(M²L)，最坏 L=O(M)；不能宣称通用 O(N log N) |
| 已保存工序重播 | Σ 单步裁切成本 | 仍按顺序执行；F 随 P 增长时，通常可达 O(P² log P)，不能把当前显示面数当成总工作量 |
| 施工阶段缓存 | 保存每一层 before/after 实体 | 空间为 Σ 阶段实体大小，层数与面数一起增长时可达 O(P²) |
| 正交投影 | O(V+I)，每条棱一个 SVG 元素 | 保持线性，棱合并为一个 path 的独立子路径，减少 DOM 更新；面填色与可见轮廓保留 |
| 3D 视口 | 面排序 O(F log F)、逐面／逐棱提交、遮挡 O(HF) | 缓存唯一棱和 retained GPU 网格，实体最多三次提交；helper 批量线段与颜色复用，同帧共享遮挡数据，保守包围盒排除明显不相交样点；精确遮挡最坏上界仍 O(HF) |

空间桶避免全局两两比较，但不能保证任意病态输入的常数查找。复杂度中的“通常”不表示所有共线、极小面或高价顶点输入都具有相同上界。

## v0.8.3 基准脚本与复跑条件

```sh
node scripts/benchmark-cut-performance.mjs > tmp/cut-performance-current.json
# 使用同一 runner 比较另一个 checkout 的领域代码：
node scripts/benchmark-cut-performance.mjs /path/to/baseline/src/domain > tmp/cut-performance-baseline.json
```

关闭其他活跃视口、构建和测试后顺序运行，避免把并发负载计入算法差异。脚本输出 Node、CPU、面数、顶点数、预热／样本数及中位数／P95；它覆盖默认 34 面实体上的 8 面草稿，96 腰部编辑、保存 96 腰部后新建 96 亭部、已有 96 亭部时原位编辑 96 腰部（3 次预热、16 个交替配对样本），以及 64／1,000／10,000／20,000 个真实三角面的凸双锥。双锥由解析坐标直接生成，不将从零构建模型的时间混入单刀计时。大规模用例样本较少，P95 只作观测，不能当成稳定的尾延迟预算。

浏览器另测实际输入捕获 → 最新几何 React 提交 → p5 绘制完成，检查每次提交的草稿与画面是否一致。绘制完成计时包含 JS 与绘图调用，不能当成 GPU 完成、屏幕扫描或显示器响应时间。保留视口尺寸、版本、模型、重复和镜像参数；按相同输入序列对照。一次性采样钩子必须移除。

## v0.8.3 扩展路线（后续状态见 v0.9.0）

1. **分开面数与历史长度预算。** 用真实球面近似、多层切割和高价顶点分别覆盖 F、P、K、H。记录长任务、内存、提交和绘制时间；除了单刀，还测中段编辑、Meet A/B、隐藏层、撤销与导出。
2. **限制前缀缓存的内存。** 将完整每层快照改成有限检查点加按需前缀，按文档与显隐版本失效；中段编辑从最近检查点重播。必须验证原序位、重合面归属、来源 stale 诊断与旧层恢复，不能只检查体积。
3. **增量裁切。** 建立顶点／棱／面的邻接与局部交界遍历，复用未受影响的面，避免每刀全量重建和排序。最坏仍可能切到全部面；验收同时核对所有平面、有效面 ID、绕序、体积与容差边界。
4. **继续缩减显示与命中开销。** 在已有网格缓存、绘制合批与包围盒预筛选上，测量机械臂、分度环和 React/DOM 更新热点；按收益增加 helper 缓存或空间索引。保留隐藏段不可见且不可命中的契约，不能只减少画出的 helper。
5. **最后评估 Worker。** 若主线程预算仍超标，再将纯几何移到 Worker，使用草稿版本丢弃过期结果，并把 helper 和实体作为同一版本显示；提交仍验证当前版本。Worker 转移线程占用，不会降低几何复杂度，也不能修复无限增长的阶段快照。

v0.8.3 当时已落地百面级批量求交、GPU 网格缓存与绘制合批；精确保存和逐刀回放仍有历史长度成本。数万面阶段应评估邻接增量裁切或对偶凸包半空间求交及 Worker，不应把当前直接边界法的百面收益外推为万面保证。完整数万面交互尚未验收，不能宣称数万面 60 FPS 或端到端 20ms 已达标。

## v0.8.3 合并前巡查（历史记录）

2026-09-08 最终检查通过 197 项领域／报告测试与 4 项 Sites 测试。350 组随机草稿的提交分类、生成／移除面数与威胁列表一致；48 组顺序核结果与旧实现的顶点、拓扑、法线、ID 和 metadata 完全一致。旧版 96 折亭尖 Meet 签名已加入长期回归。渲染对照覆盖 174,960 次遮挡查询，GPU 网格生命周期检查为 72 次分配／72 次释放。

巡查修复 Jump 候选缓存的页面暂停／恢复依赖及光学着色器资源释放，未改变交互、文件格式或状态契约。最终构建验证真实预设持久化、JSON／ASC／PDF 导出和帮助、主页、实验室、光学模式往返后的 CUT 现场恢复。

随机差分另发现旧顺序核的既有数值边界：350 组中 3 组极深冠部在完全覆盖固定台面及腰部时出现非闭合边界，批量预览为闭合体；两条路径均因覆盖保护阻止保存。此问题未进入合法提交结果，本轮保留顺序核以维护旧 Meet 身份；后续修正需同时验证闭合性与持久化签名，不能只比较体积。
