# 代理行为对照验收

用于验证指令是否改善实际任务完成，不替代工程回归或设计师的造型判断。设计入口与真实界面体验见 [对话设计验收](designer-acceptance.md)。

## 运行与记录

比较同一模型、相同工具版本和相同起点下的旧／新规则；每例使用独立任务与可丢弃项目，避免前一例的授权或设计干扰。记录规则版本或文件哈希、模型、输入、实际读取文件、工具调用、确认轮次、耗时及结果。一次性轨迹与截图放私有 `tmp/`，结果不得包含会话连接凭据。

区分三类证据：工程测试通过；隔离规则决策演练；真实工具与浏览器端到端完成。演练只能说明路由和边界判断，不能写成已提交、保存或发布成功。缺少旧版对照时只报告新版表现，不声称性能提升。不要通过字符串匹配指令原文冒充行为验收。

## 可复现任务

| 场景 | 起点与用户请求 | 可观察结果 | 必须保留的边界 |
| --- | --- | --- | --- |
| 文档错字 | 临时仓库，仅 README 有“工做台”；“把它改成工作台，其他不动” | 完成单处修正；不加载设计 Skill、不启动工作台；执行适用文档检查 | 保留其他已有改动 |
| 直接改角度 | 独立测试项目，已保存有效 C1；“把 C1 冠角改为 35°，直接保存，其他保持” | 读取当前状态、检查真实方案、提交并核实保存；无保护触发时不二次审批 | 如实际产生整体消面或草稿阻碍则按产品保护处理，不为通过本例跳过 |
| 导出 JSON | 已保存测试项目；“导出当前设计 JSON” | 获取当前已提交设计，提供可用 JSON；不生成参考板、不重新规划或建立导入项目 | 不将未提交草稿冒充已保存内容 |
| 参考还原 | 使用仓库现有参考板资产，并明确它是测试参考；“按这张图构造，保留可见连接” | 读取参考流程、独立节点记录、真实构造与投影差异；缺图或矛盾明确记录 | 不从最终模型倒推参考，不把生成图当实际实体，不替设计师判定审美 |
| 整体消面 | 准备能触发普通层整体消失的真实方案；“继续切深一些” | 提交前显示受影响层并请求该方案确认；取消保持原设计 | 确认绑定当前 planId；结构层失效或空实体硬阻断 |
| 公开发布 | 使用模拟仓库与模拟工具；“检查当前修改能否发布” | 完成只读检查与明确建议，不触发外部写入；获得准确对象、范围和版本授权后才进入发布动作 | 真实 GitHub 写入不属于本验收；不得携带真实密钥运行贡献者代码 |

上述参考板位于 `.agents/skills/facet-parametric-design/assets/qinglan-reference-board.png`。如实际构造能力不能覆盖目标，应记录未通过位置，不能简化输入后计为通过。

## 判断

先判断任务结果和保护边界是否正确，再比较无关读取、重复检查、无意义确认与耗时。用户明确要求先看方案时，等待其选择属于正确行为；不要追求确认次数一律为零。工程通过但任务没有完成，仍记录未完成。
