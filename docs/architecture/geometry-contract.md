# 几何与文档模型

维护几何求解、晶体导入、参数默认值、面身份、渲染资源或光学渲染时，读取对应条目。状态与交互规则见 [状态契约](state-contract.md)，控件与报告版式见 [视觉规范](design-system.md)。本契约规定几何唯一数据源、兼容检测与持久化边界；实现入口分别为 `faceting.js`、`indexing.js`、`concaveCuts.js` 与 `documentGeometry.js`。


- 裁切统一保留 `normal · point <= offset`：未启用凹切工具的普通立方体文档沿用凸多面体路径；导入晶体与工具差集采用保留孔、凹槽和全部分离组件的索引网格路径。数学内核独立于 React、DOM 与 p5；p5 只消费求解结果绘制。+Z 朝冠部：冠部 β 为正，腰部为 0，亭部为负；旧 JSON 导入时重新解析几何以保持兼容。
- 文档的不可变 `stock` 初始晶体、保存的 `facets` 平面 CUT STACK 与独立 `concaveCuts` 工具参数共同构成唯一几何数据源，三者职责独立；CUT 只记录切磨工序，不能用自动生成的 CUT 冒充导入原石。每个 `T/C/G/P` 图层是一份不可变参数快照，按列表顺序应用一次；编辑保存必须在原序列位置替换。图层即使暂时没有最终有效面也保留在参数化工序中，删除或撤销后续覆盖工序时可自动恢复其面。
- 普通新建文档从边长 `2.000`、轴心在原点的立方体开始，并默认包含固定首层 `T1 台面`（角度锁定 0°、深度可调、不可隐藏/删除）与可编辑的 `G1 腰部`（从所选设备盘的整除重复数中取最接近 32 的值；96 盘为 32 重、120 盘为 30 重）（深度 0.2）；清除切割恢复这两层。导入初始晶体则新建独立 mesh 项目，初始 CUT 为零，不预切 T/G。mesh 清除平切保留同一份原始晶体与凹切工具，作为一次可撤销命令。实体底胚只在创建时选择，编辑中禁止替换和缩放。
- OBJ 初始晶体导入最多 1000 个源多边形且分解后不超过 1000 个面片，超限在几何求解前阻断并提示简化；预检检查索引、退化／非共面面片、闭合、朝向及自相交，不合格禁止新建。此导入限制不改变已有 JSON 晶体文档的兼容规则。OBJ 导入保留源单位与尺寸；默认未指定单位，不猜毫米。可选择 +X/+Y/+Z 朝上并对齐工作台 +Z，按包围盒居中、最长边等比例归一到 2.000；源尺寸始终按原文件 XYZ 记录，旋转后的机台尺寸单独派生；原石面身份从规范化索引生成，不能继承外部切割工序身份。机台参考包络在导入时固定，后续 CUT 不重定尺寸或轴心。重复与镜像作用于切割指令，不复制原石。
- 实时 mesh 正交预览使用共享 WebGL 深度缓冲与真实边，静态 SVG／PDF 使用精确矢量遮挡裁分；禁止以简单面心排序取代深凹遮挡。GPU 数值缓冲按不可变实体复用，仅上传成功后更新缓存；项目卡片不各自创建 GL context，不可用时回退精确投影，不省略几何。光学渲染资源见 [光学渲染](#光学渲染)。
- mesh 的面片 `id` 与 CUT 平面 `facetId` 分离；一个平面切出多片仍是一个有效刻面，毛坯三角片不计入切割面数或助手步数。同来源共面内缝不作为真实棱显示或 Meet 目标。旧 96 分度 cube／mesh 文档继续使用 schema v1／v2；多分度、连续分度或独立凹切参数采用 schema v3，格式边界见下文。缓存、BVH 和渲染对象不得持久化。
- 每个平面图层保存自己的 `indexTeeth`（省略即 96）；内部索引为 `[0, indexTeeth)` 内的连续数值，显示值 `indexTeeth` 与内部 `0` 同位，自定义输入也接受 `0` 别名。`azimuthDeg = index × 360 / indexTeeth`；不得将非整齿方向静默取整。行业角连续且内部保存全精度，滑杆、数值框、行内编辑与 3D 手柄的最小调整步进统一为 `0.01°`，UI 至少显示两位小数；切入深度独立且保存全精度，只在 UI 显示到 0.001。
- 新建 CUT 草稿的冠部和亭部默认 8 折、腰部默认 16 折（新建文档 G1 从所选盘的整除重复数取最接近 32 的值）；镜像轴偏移默认 0。N 折取整数 `1..360`，不要求整除当前齿数。旋转轨道必须生成 N 个明确裁切平面，且新建/编辑提交时至少形成一个有效面；后续切割覆盖既有面时，最终有效面数可以减少。深度从毛坯的 Z 轴旋转包络测量，不能因方形毛坯退化成四面。
- 镜像采用二面体定义：N 折拥有分布于 180° 的 N 条无向反射轴。旋转面保留；镜像偏移可增加第二组 N 面轨道，重合面按数值容差去重，反射过程不能通过整数取整改变造型。
- 每个面记录索引、行业角、带符号 β、深度、方位角、所属图层和显式裁切平面。撤销/重做、显隐、重排和导入导出均必须保持参数化图层语义。

## 分度盘与几何的分离

设计师在新建工程时先选设备分度盘，再安排平面切磨。分度盘预设由 `INDEX_GEARS` 统一声明：32、64、72、77、80、84、88、96、99、120、360 齿；领域能力接受 1–360 的整数齿数，默认 96。`document.indexGear` 是整个项目的唯一平面切磨设备盘，其 `zeroAlias` 等于齿数，`degreesPerTooth` 等于 `360 / teeth`。所有平面层（包含默认腰棱）统一使用项目齿数。旧混合盘文件先按原参数验证，再换算 index、baseIndex、mirror 及 Meet 主分度；稳定面 ID、平面方向、深度与造型不变。不能整齿表达的方向保持小数并显示红灯，禁止静默吸附。底胚与凹切工具不参加分度匹配。

例如五折冠部在 96 齿表示为 19.2、38.4、57.6、76.8、96，在 120 齿表示为 24、48、72、96、120；两者形成相同几何。兼容性是针对所选设备的检测结果。新草稿使用项目盘，默认重复数选择该盘整除数；已有偏好分度换盘时保留方位；编辑已保存图层时使用统一换算后的项目盘。群组旋转使用项目盘齿数转为角位移；连续旋转不强制整齿。

`indexCompatibilityReport()` 只读取明确平面法线，分别输出所有工序（`all`）和最终有效面（`final`）的整齿兼容数、比例、最大角误差及不兼容面。最终范围必须传入实体求值所得的有效面身份，不能以隐藏、面列表顺序或局部预览代替。水平面不限制绕 Z 的分度，不计入需匹配的分母。角误差容差默认 `1e-6°`，在各盘统一以角度比较，界面显示精度不能改变检测结果。检测仅说明平面方位与所选盘整齿的匹配，不证明夹持、设备角度范围或凹加工可达性。

平面参数是几何输入；`azimuthDeg`、`displayIndex`、`betaDeg`、`plane` 是解析后的派生快照。导入时必须重新验证它们与图层参数相符，不能让索引与法线成为两套可独立编辑的真值。Meet、共享节点构造、视口与自动化使用同一组带 `indexTeeth` 的领域函数，不能保留另一套固定 96 的求解器。

## 持久化与校验

| 格式 | 保持条件与内容 |
| --- | --- |
| schema v1 | 旧 96 整齿 cube 文档，原参数和格式保持兼容。 |
| schema v2 | 旧 96 整齿 mesh 文档，完整保存原始晶体和 CUT STACK。 |
| schema v3 | 非 96 参考盘／图层盘、连续分度／镜像偏移、不整除 96 的重复数，或显式凹切／固定 cuttingReference 参数；内部包含独立 `concaveCuts` 数组，允许为空。导入缺失 stock／concaveCuts 分别补默认设计包络／空数组，facets 必须存在；缺省设备盘为 96。 |

`createFacetingDocument()`、新增／替换 CUT 命令与独立参数组操作在需要时升级到 v3；原有 v1/v2 项目不因打开或保存自动升级。已经采用 v3 的文档不因删除最后一条凹切工序自动降级。JSON 导出保留完整参数化工序，未形成最终有效面的历史 CUT 也不会丢失；最终指令与 ASC 范围按对应契约另行派生。

[document-v3.schema.json](../../public/schemas/document-v3.schema.json) 是自包含的 JSON Schema 2020-12。它检查数据类型、必需字段、范围、结构与有限枚举，并允许扩展字段／元数据，以保持导入器既有兼容策略；规范化输出保存正式参数字段以及声明的 metadata／extensions，安全未知可选扩展不得在项目保存或换盘时丢失。实验室公共范围、表面、毫米尺度、必需扩展拒绝规则见 [公共契约](../labs/CONTRACT.md)。图层分度上界与原盘的关联、派生法线一致性、齿数与零位别名的关联、同层主成员、Meet 来源、闭合网格拓扑及工具计算预算由 `validateFacetingDocument()` 与实体边界校验共同执行，不能用单独通过 JSON Schema 代替领域校验。旧版 schema 链接继续作为格式标识，不在本轮重写旧文件格式。

凹切工具 `id` 必须唯一，不能与任一平面 `patternId` 冲突，也不能使用保留的 `rough-cube`／`rough-mesh`；实体表面来源身份跨参数组保持无歧义。不可变的底胚和凹切数组在普通平面命令、撤销／重做中保持共享引用，避免无输入变化的渲染重复布尔计算；命令自己的平面快照仍独立保存。固定 cuttingReference 与 stock 一样在命令快照中共享不可变引用。缓存与中间网格不进入 JSON。

回归入口：`indexing.test.js` 覆盖各预设盘、1–360 折、五折等几何、两种检测范围、混合盘旋转、格式升级与撤销恢复；`documentSchema.test.js` 使用 Ajv 实际编译公开 schema，并对合法 cube／mesh、多盘样本、无效字段、跨字段不变量和扩展元数据分别验证；`cutSession.test.js`、`cutConstruction.test.js`、`sharedPlanes.test.js` 覆盖会话与构造入口。Ajv 只作为开发测试依赖，不进入网页运行时。

## 独立凹切与实体组合

设计师可以把同一组平面切磨参数用于普通底胚、已有凹面的底胚，或叠加球头、圆柱、V 轮和三角柱工具。三个参数组分别是不可变 `stock`、`facets`、`concaveCuts`；任何一组的保存不得把派生网格反写到另一组。最终实体统一求值为 `(stock ∩ intersection(facet halfspaces)) − union(enabled concave tools)`。平面与工具均使用原始机台坐标，此集合与先求差再裁切等价，不表示实际设备的加工先后顺序。平切工序历史、Meet / Jump 来源、预览有效面与影响检查只读取纯平切实体，凹切增删、移动、停用不能使平切构造失效；组合结果仍单独接受材料与边界预检。

`concaveCuts.js` 只规范化参数，保持与文档／渲染解耦。每个工具保存唯一 `id`、`type`（`sphere`／`cylinder`／`v-wheel`／`triangular-prism`）、`enabled`、中心 `position`、方向 `axis`、半径 `radius`、轴向总长 `length`、绕机台 Z 轴的 `repeat`／`phaseDeg`、曲面离散精度 `segments` 及可选 `label`。尺寸沿用机台模型单位；没有源单位时不解释为毫米。方向正规化为单位向量。旋转同时作用于工具中心、圆柱轴和曲面采样，五次对称不依赖 96 分度盘，工具重复数也不构成对设备可达性的声明。

工具几何是明确可控精度的多面片近似：默认周向 24 段，允许 12–64 段且为 4 的倍数，增加段数能减少曲面折线但增加计算成本。解析球面／圆柱参数保存在文档，渲染三角片不冒充平面切磨指令。圆柱端面标记 `surfaceType: 'plane'`，侧壁标记 `cylinder`，球面标记 `sphere`；工具产生的全部面片保留 `region: 'concave'`、工具 `sourceOperationId`／`concaveCutId` 与 `toolInstanceId`，常规 CUT 的逻辑 `facetId` 仍单独生成。

`documentGeometry.js` 的 `evaluatePlanarDocument(document)` 返回纯平切实体，`applyConcaveCuts(document, planarSolid)` 叠加工具，`evaluateDocument(document, {facets?, concaveCuts?})` 返回完整结果。`createMachiningStock(document)` 仅用于显式查看无平切时的凹切底胚；不能作为 Meet 来源、持久化 stock 或重新计算切深包络。旧凸体的边界进入 CSG 前，以原有面半空间重新建立共享边索引，保留精确 CUT 平面参数；不改变旧平切求解、顶点身份或 Meet 快照，也不对导入 mesh 做凸包近似。无启用工具时直接使用原有毛坯与平面裁切路径。启用工具时用固定版本 `@jscad/modeling` 做真实实体差集，求差阶段在居中的 100,000 单位包围盒中计算，以减小依赖库绝对误差对浅槽的影响；完成后恢复原机台坐标。经重合顶点归并与 T 形接边补齐，保留 CSG 的凸多边形及完整边界，仅分解补接后不再凸的面片，不统一插入中心扇形三角片；再通过现有闭合拓扑、朝向、壳层嵌套与自相交检查。互不相交的刀具包围盒可组成多壳工具实体一次求差；有相交可能时顺序做 BSP 差集，保留 BSP 拆分面片，避免重整时丢失极窄尖角。自相交验证遍历 BVH 节点对，每个三角形候选对只检查一次，仍执行完整窄相位与壳层检查。结果支持凹槽、贯通孔、封闭内腔和已有非凸底胚；不能用顶点下压、凸包或丢弃小片来掩盖失败。

布尔结果按不可变纯平切实体、工具数组与固定参考坐标缓存；纯平切实体变化时重新组合，切换凹切显示不重新求解或写入文档；完整求值缓存同时绑定 facets、concaveCuts 和 stock，不能把覆盖参数的结果当作默认文档结果复用。索引裁切按输入实体弱引用保留最近一次结果，键包含法线、偏移、容差、凸截面模式和完整来源元数据，供预览保存与工序诊断复用；任何输入变化即失效，不累计拖动历史。同一不可变文档的最后一次刀具操作可复用已验证准备结果，使松手保存不再求解相同参数。切过头移除全部材料或生成不合格边界时抛出明确几何错误，调用方保留当前文档／草稿，不能提交空或不闭合实体。相切、不接触或完全位于已有空腔的工具保持原实体；不以总量相对体积阈值丢弃真实微小槽。刀具半径／圆柱长度小于底胚最大边长的百万分之一时明确报告数值精度不足。最多 64 条工具工序、每条最多 120 次重复、估计工具面片总预算 60,000；预算在求值前检查，不承诺高分辨率复杂组合的实时帧率。光学读取最终材料边界，保留内腔和凹面，不退回凸体的平面求交。

回归入口为 `src/domain/concaveCuts.test.js`：验证参数冻结、体积差、真实凹面射线命中、内腔法线、倾斜圆柱加后续平面、五次对称非凸底胚、重叠工具、无效空体与空工具旧路径；`constructionHistory.test.js` 覆盖凹切变化不影响旧 Meet 来源；`concave-workspace.test.js` 覆盖预设叠加、MCP Jump、三角柱尺寸和 worker 持久化。视觉与设备加工验收独立执行。差集依赖的原始说明见 [JSCAD Boolean 文档](https://jscad.app/docs/module-modeling_booleans.html)。

凹切快捷刀具由 `src/application/concaveTools.js` 声明球形凹坑、圆弧槽、V 形尖槽、细槽和三角柱尖槽五个预设，使用固定切磨参考包络定位，读数不依赖当前平切实体。新刀具默认五次重复，默认切深为参考半径的 20% 加刀具半径的 40%；界面提供重复、整体旋转与径向深度，三角柱另提供尖角、宽度和长度。编辑导入刀具保留半径、轴向、Z、相位与精度。所有操作通过 `prepareConcaveTool` 复用完整实体预检和单步撤销，MCP `concave-tool` 同源。

实体／线框预览的普通填色仅由法线决定，以等 RGB 灰阶着色，不能按三角片中心高度分段染色。同法线面片必须同色；选中、预览与悬停仍按工序整体高亮。

`cuttingReference` 与实体 stock 分离；新底胚项目使用固定默认坐标，旧文件缺省沿用原 stock 基准以保持几何。OBJ 居中和坐标归一仅为单位映射，源尺寸、单位与 millimetersPerModelUnit 固定保留，不提供实体缩放。刀具深度始终相对固定参考，不能随着平切或底胚包围形状改变。差集缓存同时绑定参考坐标和工具数组。

JSON 的 `machining` 为导出时派生的设备声明：selectedTeeth／indexValuesUse 唯一指定数值所用盘，supportedTeeth 列出全部平切工序可整齿使用的盘，compatibleWith96 与 notice 明确 96 兼容情况。导入忽略旧的派生声明并重新检测，所有面换算为项目盘。PDF 每页页眉标示齿数，封面列出兼容盘与非 96／不兼容提示；底胚和凹切不参与分度检测。

### V 形开槽轮

`concaveCuts.type = v-wheel` 为两个圆锥侧面在圆周相交的理想刃轮，radius 是外半径、length 是完整轴向宽度；刃口夹角为 `2 atan(length / (2 radius))`。快捷预设固定 90°，轮轴沿机台 Y，phaseDeg 同时绕 Z 旋转中心和轴线。几何仍由 mesh/boolean 适配器生成封闭实体，与球刀、圆柱走同一 CSG、来源、光学链路；不是用圆锥尖端或二维星形冒充刀具。它模拟单个刃轮位置，不含沿 Z 扫掠刀路，因此高坯体可能保留上下边缘；是否贯通取决于轮半径、位置与工件高度。

依据：Ultra Tec [Fantasy Machine 手册](https://www.ultratec-facet.com/wp-content/uploads/2022/02/Fantasy-Machine-2648.7-.pdf) §5.1.1/5.1.2（圆柱磨杆、90° slitting tools）；[Nick Alexander 的工艺说明](https://fantasygemstones.com/pages/what-is-fantasy-cutting) 包括 V-cuts、grooves、bubble carving。查阅于 2026-09-22。轮缘以 segments 离散；工具分段数不代表加工分度盘，布尔结果不是设备可达性或抛光认证。

### 可调尖角三角柱

`triangular-prism` 是沿刀具轴直线挤出的等腰三角形，局部尖端朝 −X。`width > 0` 为横截面背宽，`length > 0` 为轴向总长，`0 < tipAngle < 180` 为尖端夹角；兼容定位字段 `radius = width / (4 tan(tipAngle / 2))` 表示横截面高度的一半。改变尺寸保持径向切深，除非同时显式提供新的深度。五个面均标为平面且仍归属凹切工具，不计入平切设备指令；JSON、worker、撤销、MCP 使用同一参数规范化与提交路径。

### 后台凹切结果的缓存交接

网页连续预览在独立 worker 中运行同源 application/domain 求解与闭合、自相交、壳层验证。传回的已验证最终实体，由 `receiveConcaveUpdate` 重新绑定主线程不可变 stock、concaveCuts 与完整平面／来源参数键；只接受本应用打包 worker 的结果。该通道不是文件导入入口，外部 JSON／OBJ 仍完整验证。缓存不持久化，平切参数或来源变化失效；松手与历史快照不再次求解相同实体。

## 光学渲染

光学视口的会话状态、后端回退与表面预览模式见 [状态契约](state-contract.md#光学仿真视图)；本节规定渲染不变量。测量与复测方法见 [性能记录](../cut-performance.md#2026-09-25--按设计表面的采样与降噪)，后端像素对照见 [光学后端对照](optics-webgpu-reproduction.md)。

### 共用视图与全抛光

- `opticsViewFrame` 是两种后端唯一的主机视图：像素预算（设备像素比不超过 1.5、长边不超过 1100）、相机、构图、灯光输入与阶段标记。后端只负责几何传输与追踪，不各自复制框架逻辑。
- 全抛光的 WebGPU（WGSL）与 WebGL2（GLSL）共用领域几何与 BVH 打包；凸体用半空间求交，mesh 用真实网格遍历，不以凸包替代凹体或遗漏分离组件。每像素一次确定性追踪，光滑边界按 Fresnel 分裂反射与折射，每帧完整；分辨率、反射次数、材质单位和灯光在两后端一致。
- 一次最多一个在途 GPU 提交，输入合并为最新观察；静止时不轮询或重复绘制，不声称能中止已提交的 GPU 工作。WebGPU 缓冲只在完整上传与绘制验证后接受对应的不可变 geometry；存储超限时回退，不截断几何。WebGL2 上下文丢失时暂停绘制，恢复后重建资源并重绘最新状态；相机、材质与文档不随资源重建重置，卸载须释放恢复后的实例。
- 运动时先以较低像素密度绘制最新观察位，停下后恢复完整分辨率：全抛光经 45%、70% 到 100%；采样模式只用 50% 与 100%，因为每次改变分辨率都会重新累积。共享导航缓动的剩余量小于半像素时，视口直接使用目标观察位并按静止绘制，采样才能继续累积。

### 按设计表面

- **材质**：按 `facetId ?? id` 关联逐面 `surfaceFinish`，每个图元材质为 `[alpha, scatter, 面序号 + 1, 0]`；毛坯与没有标注的新凹切边界缺省抛光。版本 1 参数与实验室公共契约共用 `isSupportedSurfaceFinish` 校验，不支持时明确失败，不以抛光画面冒充。
- **几何**：凸体且面数不超过 512 时，半空间与逐面材质写入一个 std140 uniform 块（WebGL2 保证的最小 16 KiB），按平面求交；其余实体使用 BVH 三角形，材质在 BVH 重排后解析。凸体上离开宝石的光线不会再次命中，直接读取环境，每条路径保持线性；mesh 仍按深度优先处理可能再次入射的光线。
- **传输**：光滑边界使用与全抛光相同的确定性分裂，纯抛光路径与全抛光结果一致且没有采样噪声。磨砂边界直接引用固定实验室模块的 GGX 介质模型（`evalBSDF`、`visibleNormal`、`fresnel` 与随机维度），每次交互一个 BSDF 采样加一个灯板采样，以功率启发式合并；非凸体的灯板采样做遮挡测试。环境采样由均匀球面与四个灯板的余弦幂瓣混合，常量与 `environmentRadiance` 一致并由测试核对。路径起止都在宝石外，进出的 η² 辐亮度压缩成对抵消，与全抛光一样统一省略。三个色散波段共用随机维度；色散为 0 时只追踪一次。
- **累积与显示**：RGBA32F 线性累积颜色与亮度二阶矩；每个样本亚像素抖动以抗锯齿，背景按显示值反解为线性值，使轮廓在同一空间平均。第一批同时写入相机中心光线的面身份、法线及是否触及磨砂。显示前做三遍 5×5 边缘感知 à-trous（步长 4、2、1）：只处理触及磨砂的像素，邻域须同面同法线，亮度差按该像素均值的标准误加权（样本少于 4 时用同面邻域方差估计）；样本增加后滤波自动减弱，纯抛光像素保持原值。这是只作用于显示的有偏滤波，不改变累积数据。
- **调度**：运动中每帧 1 个样本；静止后每批样本数按 fence 完成时间在 1–16 间自适应（一帧内完成则增大，超过约 36 ms 按比例减小），避免单次提交长时间占用 GPU；累积到 128 个样本后停止，不空转。几何、标注、相机、尺寸、材质或观察设置变化时重新累积。
- **资源**：只有存在有效磨砂面并选择按设计表面时才延迟加载；缺少浮点缓冲时明确报错，可切回全抛光。模式切换、卸载与上下文丢失释放程序、纹理、帧缓冲和 uniform 缓冲，迟到的异步实例同样释放。此模式只有 WebGL2 实现，不宣称 WGSL 已支持粗糙介质。
- **适用范围**：`alpha` 与 `scatter` 是渲染模型参数，没有对砂目、抛光粉、工时或实物标定。预览用于在相同几何、相机、材质与灯光下比较磨砂与抛光的相对观感，不是能量参考渲染，也不承诺实物效果。更新或回退实验室模块时，须同步复核 `opticsSurfaceShader.js` 与 `viewportNavigation.js` 的固定引用；测试会对照 `labsModuleLock.json`。
