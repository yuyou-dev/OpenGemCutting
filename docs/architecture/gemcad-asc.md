# GemCad ASC 兼容说明

格式实现见 [gemcadAsc.js](../../src/domain/gemcadAsc.js)，当前文档职责见 [索引](../README.md)。导入、导出与跨格式转换都在[格式中心](format-center.md)进行；ASC 与 Gem Cut Studio、GemCAD `.gem` 共用其中的中立平面模型。

## 底胚与凹切边界

导入 OBJ 初始化的 mesh 项目一律阻断 ASC 导出，即使当前外形看起来已凸，也不绕过预检。ASC 不能完整保存初始凹原石、面片和 CUT 历史；请使用原生 JSON 完整项目继续设计或交接。启用的凹切刀具同样阻断 ASC 导出；已停用凹切不影响当前实体，但预检明确提示其参数不会进入 ASC。不得将曲面网格三角片冒充真实平面加工工序。

## 支持范围

Facet 96 读取 GemCad 5.0 文本 ASC，保留源齿盘的正整数齿数与小数分度，并按当前文档选择的齿盘导出。支持 1–360 齿，常用检查清单为 32、64、72、77、80、84、88、96、99、120、360。负齿盘用于源方位反转，导入后的齿盘齿数为正值。解析器同时兼容带警告的 4.x 文件、UTF-8 BOM、LF/CRLF、缺少 `g` 前缀的真实文件，以及以数字、`n` 或 `G` 开头的续行（折行的层保留全部索引、刻面名与说明）。负索引或大于齿数的索引按齿盘循环换算到同一方向并警告。

ASC 是几何交换格式，不是完整项目格式。JSON 仍是唯一完整主文件；ASC 不保存撤销历史、隐藏状态、底胚、凹切刀具、CUT 会话、磨砂表面及除折射率以外的光学设置。Gem Cut Studio 的 `.gcs` 是 XML 文本格式（不是二进制），与 GemCAD 自己的二进制存档 `.gem` 都由格式中心单独读写，规则见[格式中心](format-center.md)。

权威参考：

- [GemCad for Windows 用户手册](https://www.gemcad.com/downloads/gemcadman.pdf)，第 15 页定义 center-to-facet distance，第 20 页定义 ASC 记录。
- [GemCad DOS 用户手册镜像](https://manualzilla.com/doc/5697220/gemcad-user-s-manual)，用于交叉核对带符号齿轮与 location。
- [MIT 开源 GemCad reader](https://github.com/mbparker/gemcad-file-reader)，用于交叉核对 gear location 的有效方位公式。

## 文本结构

| 记录 | 语义 | 当前处理 |
| --- | --- | --- |
| `GemCad 5.0` | 文件签名 | 必需；4.x 警告兼容 |
| `ggear location` | 带符号齿数、齿位方位 | 保留齿数，方向为 `(index - location) × 360 / gear`；也接受 `g gear location`，真实样本的裸 `gear location` 警告兼容 |
| `y folds y/n` | 保存时的全局对称设置 | 作为元数据保留，不用于猜测 tier |
| `I value` | 折射率 | 写入 `metadata.optics.refractiveIndex` |
| `H text` / `F text` | 最多四行标题/脚注 | 保留并再次导出 |
| `a angle distance ...` | 一个刻面 tier | 一个不可变 CUT STACK 图层 |
| `n name` | 紧邻前一个索引的刻面名 | 逐面保留 |
| `G text` | tier 切割说明 | 行内或下一行保留 |

`y` 是保存文件时的当前工具设置，不描述此前每一层如何生成；因此 `a` 行的显式索引列表始终是几何真值。导入层使用同一 `patternId`，每面保存 `repeat: 1`、`mirror: 0`、`baseIndex: index` 与 `patternMode: "arbitrary"`，不擅自反推对称参数。

## 转换规则

- ASC 行业角带符号：负值为亭部，正值为冠部，`±90°` 为腰部；`0°` 且负距离为底尖，其他 `0°` 为台面。
- 内部几何 `β` 为 `sign × (90° - |angle|)`；冠部为正，亭部为负，腰部为 0。
- 有效源齿位为 `index - gearLocation`。导入保留绝对齿数 N，并保存 `(index - gearLocation) × sign(gear)` 的循环归一化值；允许小数，不做整齿吸附。带符号源齿数和相位仍保存在 `metadata.asc`。每面 `indexTeeth` 指明其创作时的齿盘，缺失字段按历史 96 解释。
- ASC 第三列是原点到切割平面的法向距离。导入整份文件使用同一比例 `s`：`depth = rotationalSupport(normal) - s × abs(centerDistance)`，`s` 同时满足全部深度非负与闭合宝石整体在毛坯内（规则见[格式中心](format-center.md#进入工作台的统一比例)）。这会保持角度、索引、平面距离比、L/W 与高度比例；发生缩放时预检明确显示百分比。
- `T1` 按 Facet 96 不变量提升为 CUT STACK 固定首层，但原 ASC tier 序号保存在元数据中；再次导出会恢复源工序顺序。
- 缺少 `0°` 台面或包含多个 `0°` 台面的 ASC 不能在工作台打开；负距离的 `0°` 底尖属于亭部，不计入台面数量。静默补台面或猜测固定 T1 都会虚构源工序。这类设计仍可在格式中心直接转换为 GCS，不经过工作台。
- preform 记录当前阻断。应先在 GemCad 中把预形复制为真实刻面。

## 导出规则

完全空实体或没有有效平面工序时阻断导出。亭部平底尖写为 `0°` 加负距离，读回仍是亭部底尖。磨砂面写为普通刻面并提示；磨砂只保留在 JSON 与 GCS。普通立方体仍保留初始面时，明确警告 ASC 不包含这些底胚边界，不能独立还原完整外形。只导出完整已提交实体中仍有效的平面；被覆盖的历史面不导出，临时显隐不改变出口几何。已锁 Meet 的来源、比例点和预形用途不随 ASC 传递，预检须明确省略范围。

导出写出 `GemCad 5.0`、`gN 0.0`、显式 tier 索引、折射率、标题、脚注和切割说明，行尾与 GemCad 自身文件一致使用 CRLF（Gem Cut Studio 1.1 读取仅 LF 的 ASC 时会把最后一个名称读成“Tÿ”），N 来自 `document.indexGear.teeth`。方向从每面真实平面法线换算到 N，不能直接重标原始索引数字；小数照写，仅清理浮点尾数。预检给出最终有效平面的整齿兼容数量、最大角误差与容差。整数不兼容不会使几何丢失或被偷偷取整；例如 96 盘的一齿映射到 360 盘仍为 3.75 齿。水平台面不受方位齿盘约束。每组有效刻面必须共享行业角与平面距离；否则不能表示为单个 ASC tier 并阻断导出。

导入和导出都在格式中心先显示来源概况（齿盘、层／面数、磨砂面、折射率、L/W）与去向报告（保留／简化／丢失／不能转换及技术细节）；错误阻断，有损时由“了解差异，导出”一次确认。导出后读回核对形状，不一致即阻断。

重复与镜像会展开为显式索引。几何保持，但参数化生成意图不可逆；导出预检会提示。中文或其他非 ASCII 标题使用 UTF-8 写出，旧版 GemCad 的显示编码需要人工确认。

## PDF 加工报告

`src/report/pdfReport.js` 使用 `evaluateDocument(document)` 重新计算完整已提交实体，不复用可能受显隐或临时预览影响的调用方网格。平面表仍只包含最终有效 CUT 平面；旧混合齿盘文件导入时统一换算到项目盘，表中索引由真实法线映射到该盘，完整工序保留在原生项目。

封面标明实际报告齿数与最终平面整齿兼容状态。新增凹切附录独立列出球刀/圆柱刀/V 形轮的启用状态、半径、全长、位置、轴向、重复次数、起始方位和网格精度。凹曲面数量不会冒充平切指令数量。已有凹面底胚与新增凹切设备要求分别说明；所有尺寸沿用项目单位，不猜毫米。PDF 是几何和参数交接，不代替刀具可达性、机床行程及装夹验证。
