# Community triage rules

- `Q&A`: answer with verified product behavior; mark an answer only when it resolves the question.
- `Ideas`: clarify the desired cutting or reporting outcome before turning it into implementation work.
- `Show and tell`: acknowledge the contributor and preserve attribution for shared cut designs.
- Bug Issue: record environment and minimal steps, reproduce with public-safe data, then recommend fix, defer, or close.
- Pull Request: verify intent, actual diff, repository contracts, tests, public boundaries, and authorship before recommending merge.
- Duplicate: link the canonical item and retain any useful new evidence before closing.
- Security or secret exposure: move the report to the private security channel; do not repeat sensitive content publicly.
- Spam or unsafe content: recommend moderation with a concise reason.

After action, close the loop with the implemented change or decision, thank the contributor, and update recurring documentation when appropriate.
