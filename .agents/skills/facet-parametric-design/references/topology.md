# 参考拓扑与最终实体检查

## 构建之前确定检查对象

将参考图分成台面周界、冠部扇区、腰线和亭部扇区；先用语义名称记录每个目标共点参与的面、连接到的相邻节点，以及参考位置。图中本来有短棱时保留两个节点，不能为了“共点”把它们合并。标记用户批准的大面例外，明确其边界。实际 CUT 生成后只补上语义面到 facet ID 的映射，不据生成结果删改目标。

每个预期生成的面都需有结果；无解应报具体缺项。分组数、对称性、Meet valid、点到无限平面的距离均不能代替最终实体拓扑检查：无限延长线的交点可能已被其他 CUT 截掉，或落在实际面片之外。

## 检查范围

对每一个必需共点，确认参与的是指定的面，而不只是“有四面／五面”；确认它们在最终实体的同一个顶点相接。对每一条预期棱，确认端点之间存在由指定两面支撑的真实边链，不能只靠顶视投影交叉。额外小边／小面可能说明目标被分裂，需要回看相邻所有面。检查完整序列后重做，不能只验创建该面时的施工前缀。

mesh 的共面三角片不是多个刻面。脚本用 `facetId` 合并面身份，保留真实顶点连接；不靠放大几何容差“焊接”原本分开的节点。凹底胚用 mesh 专用几何检查，不用凸体半空间检查否定原始凹面。

## 可执行清单

调用 `scripts/inspect.mjs design.json reference-topology.json`。清单格式：

```json
{
  "nodes": [
    {"id":"table-right", "reference":"原图台面右角", "facets":["table-id","main-right-id","star-right-id"], "exact":true},
    {"id":"crown-right", "reference":"右侧主面与星面汇点", "facets":["main-right-id","star-right-id","upper-right-id"]}
  ],
  "edges": [["table-right","crown-right"]]
}
```

示例 ID 须替换成该设计的真实 facet ID。`exact` 可用于明确不允许额外刻面的点；不确定时先根据参考判断，不要直接设为 false 来绕过失败。两个棱端点的面集合应恰好共享两个支撑面。缺清单为 `unassessed`，缺节点或缺连接为 `failed`。脚本通过只表示清单内关系成立，不能自动证明清单完整或参考相似。

测试脚本：`node --test .agents/skills/facet-parametric-design/scripts/topology.test.mjs`。其中“小倒角把一个顶点分裂成几个近邻点”的反例必须失败，即使实体仍然闭合。

## 人工检查不能省略

补做一次反向覆盖检查：从最终实体枚举台面周界的全部真实转角，逐个对应事先定义的节点，不能只验证清单中的点存在。忽略同来源共面三角剖分产生的直线细分点；额外转角、短棱或小面必须说明用途，否则视为待修。冠部外圈、腰部落点和亭部分叉也按各自语义区域核对，不能用一个区域的通过代替另一区域。

清单中的参与面由设计用途与构造关系决定。不要仅把“经过生成点的所有平面”自动填进清单后自证通过；平面残差适合作为附加检查，仍须独立核对预期身份、数量和邻接。自动检查器只检查所给清单，尚不自动检查整圈覆盖或额外转角。

将原图和同一保存 JSON 的真实正交预览等高或等宽对齐，保持各自比例。在正常工作台大小先看一遍，再放大台面周界和每个扇区。按清单逐项标记匹配、失败、未确定、已批准例外，并标出不在清单内的可见错接。尤其不能只展示选中几个共点的数字来声称整张冠部正确。

工程报告与设计判断分开：说明检查了哪些完整区域，哪些局部按批准简化；可见错接仍存在时继续修复或提出具体替代方案。不要把失败包装成一般的“像素误差”或“低清图近似”。
